# 时间渐进性测试流程

## 1. 测试目的与赛题口径

项目文档要求最终JD验收集不少于100条，且来自去重后的计算机相关真实JD。本测试采用100条真实JD作为基线事实，通过受控模拟补足短期内真实岗位变动稀疏的问题，检验系统是否能够识别新增基线、无变化、字段更新、技能新增/移除、岗位上下线及月度市场演化帧。

本套件是“时间变化捕捉能力测试集”，不是JD解析金标集。两者必须分开报告：

- 解析金标集回答“字段抽取得准不准”，需要人工双标与仲裁。
- 时间渐进集回答“已知变化能否被流水线发现并形成版本与演化结果”，变化由生成器提供ground truth。

## 2. 数据来源与抽样

1. 输入为仓库 `data/talentgraph-db.zip` 内的SQLite在线备份。
2. 只读查询 `job_assets.payload`，绝不解压覆盖生产库。
3. 只允许智联、BOSS、前程无忧和猎聘四个正式招聘来源。
4. 排除模拟标记、非目标领域、下线、正文少于300字符、技能少于3项、缺失公司/来源URL和重复哈希记录。
5. 按四领域各25条分层，再使用固定种子与SHA-256排序抽样，避免人工挑选偏差。
6. 对公司、ID、URL和联系方式脱敏，保留岗位内容结构、领域、技能、职责、经验、学历和薪酬等测试所需统计特征。

## 3. 时间与场景设计

时间轴为2025-09至2026-08，共12个月。100个岗位固定分配为：

| 场景 | 岗位数 | 验证重点 |
|---|---:|---|
| 稳定对照 | 15 | 重复监测应判为 `unchanged`，不产生新版本 |
| 技能渐进增长 | 25 | 新技能被清洗器抽取，Store记录 `skill_tags` 变化 |
| 技能迁移 | 20 | 技能新增/移除均有可核对差异 |
| 薪资渐进 | 15 | 薪资上下界变化进入版本字段差异 |
| 经验门槛收紧 | 10 | 最低经验要求变化进入版本字段差异 |
| 下线与恢复 | 10 | `job_status` 在 active/offline 间切换 |
| 多字段复合变化 | 5 | 同一观测同时捕捉技能、薪资、经验变化 |

各岗位通过固定哈希获得不同变化相位，使变化分散在12个月，而不是集中在单月。所有事件写入 `ground_truth.jsonl`，包括预期结果、字段变化和技能增删。

## 4. 流水线执行

自动化脚本严格复用项目现有实现：

```text
压缩原始观测
  → normalize_recruitment_item（范围、清洗、技能、职责、证据）
  → CleanedDataItem / CleanedDataBatch（Schema校验）
  → AppStore.ingest_live_batch（身份、去重、new/updated/unchanged）
  → job_observations / job_versions（观察与版本）
  → EvolutionAgent.analyze_market（月度市场演化帧）
  → KnowledgeGraphService.build_career_galaxy（三维图谱数据构建）
```

`AppStore.save_job_version`默认写入机器当前时间，适用于在线监测但不支持历史回放导入。测试夹具在隔离库内把刚生成版本的 `changed_at` 改为ground truth观测时间，以验证月度演化；这一步不会修改业务代码或生产数据库。若未来要正式导入历史数据，应新增受权限控制的历史回放接口，而不是复用在线采集接口。

## 5. 验收规则

以下条件全部满足才判为通过：

1. 1200条观测全部通过现有清洗与Schema校验。
2. `new`、`updated`、`unchanged` 三类结果与ground truth逐月计数完全一致。
3. 所有预期变化字段均出现在版本diff中，字段召回率100%。
4. 预期技能新增与移除均被捕捉，无漏检。
5. 版本时间能形成全部有事件月份对应的演化帧。
6. 最终活动岗位能够生成非空三维图谱节点和关系。
7. 全过程只写临时数据库，生产数据库文件哈希与内容不变。

## 6. 执行命令

仓库根目录：

```powershell
# 单独执行并生成可读报告
python .\temporal_progression_test\run_validation.py

# 纳入pytest规程
python -m pytest -q .\temporal_progression_test\tests\test_temporal_progression.py -o addopts=

# 项目全量回归
python -m pytest -q -o addopts=

# 前端兼容性
Set-Location .\apps\web
pnpm run build
```

输出报告位于 `temporal_progression_test/reports/latest.json` 和 `latest.md`。

## 7. 结果解释与限制

- 100%变化捕捉率只证明预设场景在当前规则下可被发现，不等于未来真实市场预测准确率。
- 模拟技能变化来自领域技能池，能够验证工程链路，但真实趋势方向仍须由连续真实采集和跨源证据确认。
- 当前市场演化按“有版本事件的日期”建帧，无变化月份不会单独生成版本帧；报告会同时保留12个月逐月观察计数。
- 当前三维图谱读取岗位资产的当前快照，岗位历史由 `job_versions` 和演化接口表达；图谱本身不会从历史版本自动重建每月真实岗位资产。
- 正式提交前应冻结代码提交ID、数据库快照哈希、数据集哈希和本次报告，并安排人工复核抽样记录。

## 8. 回滚与清理

测试不改业务代码和生产数据库。需要移除时，只删除 `temporal_progression_test` 文件夹即可；临时SQLite测试库默认位于系统临时目录并在进程结束后清理。仓库中的数据集可由固定种子重新生成。
